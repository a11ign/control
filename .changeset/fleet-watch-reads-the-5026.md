`fleet-watch` reads the Windows build spread on every reading and files ONE stop-the-line incident (a11ign/a11ign#5026, #4405). `src/fleet-build-incident.ts`: when two reachable boxes report different `windowsBuild`s, one issue in `a11ign/a11ign` is filed, labelled `incident`, `lane:orchestrator`, `ready`, `priority` and `out-of-release`, titled `Mixed Windows build across the fleet: <n> boxes behind <target>`, naming each laggard with its build and carrying `Incident: incident:fleet-build-mixed` on a line of its own (`FLEET_BUILD_INCIDENT_LINE`; `openFleetBuildIncident()` is the one reader). The target is the HIGHEST build compared as dotted numbers, not the most common. OPEN means the line is stopped: it is not commented on again each tick, a second open one is closed as a duplicate, and it is closed with the final reading only when the fleet reads one build AND every box in the inventory was read. A `gh` that cannot be asked is `CANNOT_ASK`, never QUIET; a filed incident is ATTENTION and a line in the #928 post; without `--post` the effects are only said. Revert: drop the `buildIncident:` line in `fleet-watch.ts`'s `main()`; the watch then reads as before.
