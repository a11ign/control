The fleet's Edge pin follows forward to `156.0.4314.42` (A11-183), the Edge updater is held by a guard that can do it, and `fleet:status` fails on a build split. The fleet had split three ways on Edge (155.0.4283.45, .62 and 156) because the guard task failed on every run: it runs as SYSTEM, and the `edgeupdate` service's security descriptor gives SYSTEM no `SERVICE_CHANGE_CONFIG`, so `Set-Service -StartupType Disabled` threw under `$ErrorActionPreference = 'Stop'` before the record was written, and nothing said so.

`edge-version.yml`: the role stops any running `MicrosoftEdgeUpdate*` or `MicrosoftEdge_X64_*` process before it installs (on a11y-worker-11 the updater was installing 156 itself with its service and tasks `Disabled`, and the pinned MSI failed with error 1722), the guard repeats from a `time` trigger with no duration (a daily trigger with a one-day repetition does not begin repeating after a registration until the next midnight, so the guard went quiet on every box it was re-registered on), and the guard writes the start type through `HKLM:\SYSTEM\CurrentControlSet\Services\<name>` (`Start` 4), stops any running `MicrosoftEdgeUpdate*` process, handles each task, service and process on its own, always writes its record (with a new `failed` key) and exits non-zero when anything stayed on. The closing assertion starts the guard and requires a newer record, result 0 and nothing it could not change. `firewall.yml` blocks `MicrosoftEdgeUpdate.exe` outbound on every profile as a second lever, and proves the rule. `worker_edge_version`, `worker_edge_msi_url` and `worker_edge_msi_sha256` move to the newest Stable x64 MSI (published 2026-10-22); `worker_edge_allow_downgrade` stays `false`.

`fleet-status.ts` reads each box's own Edge, NVDA and Windows build and the guard's state: a split, a box that reports no value, or a reported guard state other than `ok` (a worker that sends no `edgeUpdaterGuard` at all is named UNREAD and is not a failure) prints `fleet BUILD SPLIT` / `fleet Edge updater NOT HELD` naming the boxes and values, carries the reading as `buildSplit` in `--json`, and exits **3**, the code `capture-fleet-guard` uses to refuse an inconsistent fleet. `fleet-converge.ts` reads exit 3 as `failed`, not `unknown`. `edge-pin-parity.test.ts` declares `BOOTSTRAP_LAG` (the previous whole pin) because control's fleet layer stays at 0.11.0 until the core's lock moves to 0.13.2, which carries the new bootstrap pin.
