Nothing on a fleet box upgrades by itself (A11-205, step 2 of 5). `ansible/roles/worker/tasks/freeze.yml` holds every lever that stops a self-updater, values included and none of them in `defaults/main.yml`: Windows Update (`NoAutoUpdate`, `UseWUServer` with an unreachable `WUServer`/`WUStatusServer`, `DoNotConnectToWindowsUpdateInternetLocations`, the target release held at the manifest's, the driver exclusion, `wuauserv`, `UsoSvc` and `WaaSMedicSvc` at `Start=4`, the Update Orchestrator, Medic and Store scan tasks disabled, Medic's TrustedInstaller-owned keys handled through a one-shot TrustedInstaller task), the Edge updater (services off, `MicrosoftEdgeUpdate*` tasks unregistered, every updater binary renamed to `*.a11y-frozen`, one outbound block rule per binary), the Store (`AutoDownload=2`, `InstallService` off) and Defender's signature updates (reported, not fought). The Windows Update deferral (30 days quality, 365 days feature) is deleted from every box. The role runs the freeze on every provision; `ansible/freeze.yml` re-applies only the freeze to every reachable box and names the ones it did not reach; `fleet:freeze-schedule` installs `a11y-fleet-freeze-daily.timer` and removes the patch window. `fleet:freeze-proof -- --limit=<box>` shows each lever holding from the box. The Edge install is a block whose `always:` freezes, the 15-minute Edge guard now only reports, NVDA's update check and the add-on store's are turned off by a new `a11y_nvda_updates` module and an NVDA that is not the manifest's is refused, and `patch.yml` lifts only the Windows levers and freezes again in `always:`. The 28-day patch window is removed: `patch-schedule.yml`, `fleet:patch-schedule`, `--scheduled` and its window flags, the patch run record and `fleet-watch`'s `patch-window-missed` line.
